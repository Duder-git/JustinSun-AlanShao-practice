# 03-先升级操作系统：认知笔记系统

> 对谈原话（约 00:12:21）：「孙学」就是理论武装自己……大脑相当于升级，你操作系统总得换嘛。
> 对金钱、对财富自由、对万事万物的理解，都要当成操作系统，隔一阵升级一次。
>
> **实践平台**：Obsidian（推荐）或飞书文档 / 飞书云盘。

**状态**：✅ 已实现（方案细化完成，可照做）

## 核心思路

把「看法」当代码、把「验证」当测试：每天写下看法，用资料和 AI 去验证，被证据说服就更新并留记录。这样攒下来的，是一套**会随证据升级**的个人判断体系。

- **每天写下 1 个看法 / 判断**（认知条目）
- **对每个看法找资料验证**（搜索、文献、数据），标注状态：**已验证 / 被推翻 / 待验证**
- **定期回顾**：哪些看法被事实更新了 = 操作系统升级成功
- **AI 当验证助手**：把看法丢给 AI，让它找反例和证据

## 目录结构（认知笔记）

```
认知笔记/
├── 判断/                     # 每条看法一个文件（模板见下）
│   └── 【主题】.md
├── 资料/                     # 支持与反对的一手资料原文（只读，不许改）
│   └── 【主题】/来源-日期.md
└── 回顾/                     # 定期回顾报告
    └── YYYY-W周.md
```

## 认知条目模板（判断/【主题】.md）

```markdown
# 【主题】

- 创建日期：
- 当前状态：待验证 / 已验证 / 被推翻

## 我现在怎么看
（一句话说清观点）

## 我凭什么这么看
（1-3 条依据，尽量可查证：来源、数据、经历）

## 看到什么我会改主意
（写清证伪条件；写不出来 = 观点还不清晰，先回炉）

## 验证记录
| 日期 | 证据来源 | 支持/反对 | 结论 |
|---|---|---|---|

## 更新日志（操作系统升级记录）
- YYYY-MM-DD：旧看法 → 新看法，因为【资料/来源】
```

## 日常流程

1. **每天写下 1 个看法**：用上面的模板在 `判断/` 新建文件；优先写你最近一直在想的事
2. **找资料验证**：搜索 / 文献 / 数据，支持和反对的都找，原文存入 `资料/【主题】/`（标注来源链接与日期）
3. **AI 挑错**：让 AI 只根据 `资料/` 里的内容给你的看法挑错，逐条标出处（prompt 见下）
4. **更新状态**：有强证据支持 → `已验证`；被证据推翻 → `被推翻` 并写更新日志；还没把握 → 保持 `待验证`
5. **定期回顾**（每周或每月，写进 `回顾/`）：
   - 状态汇总：几个已验证、几个被推翻、几个待验证
   - 哪些看法被事实更新了（这是操作系统升级的直接证据）
   - 哪些判断最值得信任（多次验证仍成立），哪些是盲区
6. **一个问题想清楚了，再开下一个**：不贪多，一条条来

## AI 验证助手（可直接复制的 prompt）

把看法丢给 AI，让它找反例和证据：

```text
帮我验证一个看法。
我的看法是：【填入你的看法】。
请做四件事：
1. 联网找 2-3 份支持我的一手资料（带来源链接和日期），原文整理后存到 资料/【主题】/。
2. 再找 2-3 份反对我的一手资料，同样整理存档。
3. 只根据这些资料逐条给我的看法挑错，每条都标出处。
4. 最后判断：这个看法应该标 已验证 / 被推翻 / 待验证，并说明理由。
```

## 平台选择

| 平台 | 说明 |
|---|---|
| **Obsidian（推荐）** | 本地 Markdown 文件，判断与资料可用双向链接互相引用；可配合 Obsidian Sync（付费）多端同步；换工具也不丢 |
| **飞书** | 用飞书文档 / 云盘搭建同样结构（判断、资料、回顾三文件夹）；可与观点 01 的个人 AI 数据库统一存放，豆包直接读写 |

## 升级判据（怎么算「操作系统升级」）

- 回顾时出现「被推翻」或「依据更新」的条目 = 升级发生
- 三个月内没有任何看法被更新，说明输入不足：加大资料量或换个领域
- 目的不是「永远正确」，而是让看法随证据更新——旧的被推翻不可怕，不更新才可怕
